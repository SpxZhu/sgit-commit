# 提交执行规则

单独调用技能或用户要求执行本地提交时读取。先只读核定候选范围并在一个文本块中展示主题、空行及编号正文；用户明确确认这份文案与范围后，才允许暂存和提交。最初的提交请求、单独调用技能或对其他方案的确认均不能跳过展示与等待。明确只生成文案时不进入提交分支。一次明确确认同时授权该范围的暂存与本地提交；宿主权限审批与仓库强制门禁仍然有效。

## 1. 只读核定候选范围

确认仓库、分支、当前 HEAD（首次提交可能没有 HEAD）及现有暂存状态。保留用户已有工作。出现未解决冲突、正在进行的 merge／rebase／cherry-pick、特殊索引状态或仓库不明确时，停止提交分支并说明，不自动初始化仓库或接管这些操作。子模块、嵌套仓库不递归自动提交。

将文案候选落实为确切文件／变更块。标明已暂存、未暂存和未跟踪内容，以及明确排除项。明确要求“仅已暂存”时，候选范围只取索引快照，不混入工作区最新版。重命名核对新旧路径，删除核对删除意图；混合变更只选明确的变更块，无法可靠隔离时保留现状并说明。

暂存区已有范围外内容时，在任何写入前停止并说明；未经授权，不通过取消暂存、stash 或重写索引来腾空暂存区，也不把那些内容一起提交。多个独立任务可以提出拆分建议，但不擅自创建多个提交。

展示完整候选文案和范围后等待用户明确确认；用户修改其中任何一项时，更新候选并重新等待确认。

**完成条件：用户明确确认了具体的文案与候选范围；未选内容保持原状。**

## 2. 确认后暂存并以最终索引重核文案

确认后只暂存已审查且属于确认范围的内容。明确要求“仅已暂存”时不重新 `git add`；整文件全部属于该范围才可使用 `git --literal-pathspecs add -- <路径…>`。禁止以 `git add .`、无范围的 `git add -A`、`git commit -a` 或给 `git commit` 追加路径来绕过范围核查。

暂存完成后，重新检查完整待提交范围的 `git diff --cached`，按需分批读取；按 SKILL.md 的文案规范重新核对。先前工作区预览不是最终提交依据。若最终索引或所需文案与用户确认的内容有实质差异，展示更新后的范围和完整文案并重新等待明确确认，然后再提交。

执行 `git diff --cached --check`，遵守项目已有的提交前验证要求；仅复用仍适用于最终索引的证据。`--check` 不等于功能测试。检查命令失败要区分实际错误与“存在差异”的正常退出码；例如 `git diff --cached --quiet` 返回 0 表示没有暂存差异，返回 1 表示存在差异。没有待提交变化则结束，不创建空提交。

检查所选内容中的明显凭据、私钥或意外生成产物；发现风险时在不泄露内容的前提下报告，不静默改代码或扩大排查。记录 HEAD 和已审查索引快照；提交前发现分支、HEAD 或索引变化时重新核查。前置 hook／格式化产生的新变化也需重新审查，不盲目暂存重试。

**完成条件：整个待提交索引恰好等于确认范围，主题、编号正文与最终索引一致，适用门禁没有未解决阻塞。**

## 3. 创建并核验本地提交

将“主题＋空行＋编号正文”写入系统临时目录下唯一的 UTF-8 无 BOM 文件，再用 `git commit -F <消息文件路径>` 提交；支持可靠标准输入的工具也可使用 `git commit -F -`。通过文件／参数接口传递数据并正确处理路径引用，不将文案拼接成可执行 Shell，不依赖字面量 `\n` 生成换行。不要给此命令附加路径参数。

保留现有身份、签名及 hooks；不自动改 Git 配置，不用 `--no-verify`、关闭签名或其他方式绕过失败。不执行 push、amend、reset、rebase、清理文件或覆盖用户修改；它们不属于本技能的提交授权。

成功后核对新提交的 HEAD／父提交、实际差异及 `git log -1 --format=%B`，再查 `git status --short`。报告短哈希、实际主题、编号正文和剩余未提交内容；只有证据支持才声称工作区干净。若 hook 或并发操作改变了结果，明确报告不一致，不自动 amend 或回滚。

失败时报告具体阻塞及当前暂存状态，不声称成功，不扩大范围重试。仅清理本次创建的临时消息文件，保留仓库现场。

**完成条件：实际提交内容和文案均已核验，范围外改动仍然保留；或明确报告未提交及原因。**
